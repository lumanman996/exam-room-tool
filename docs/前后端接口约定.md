# 前后端接口约定

保持现有接口兼容。所有 POST /api/<name> 使用启动口令，响应 {ok:true,data:...} 或 {ok:false,error:中文说明}。保存/确认预览使用 revision，旧 revision 不覆盖新编辑。新增能力由 state.capabilities 控制；只有测试后真实可用能力才置 true。

- import_preflight / import：{kind,rows,mapping,mode:'append'|'replace'|'update',revision}；兼容原 append 布尔。preflight 返回 {rows,errors:[{row,field,code,message}],warnings,added,updated,removed,revision}。row 为数据行 1-based（表头后的第几条），row=0 表示整批/已有资料问题。姓名不用于学生更新匹配；用唯一学号/考号，匹配歧义拒绝；替换保留强身份可识别的 ID，清理已删除资料关联。

- settings.exam_groups=[{exam_ids:[...]}]：明确指定同时混考场次，至少两个不同年级，时长须一致。mix_groups 仍是允许同场的年级范围。
- numbers/number_preview 增加 prefixes（年级 -> 文本前缀），保存到 settings.number_prefixes；原 prefix/grade 方式仍可用。
- recovery_preview({id}) 返回 available/name/revision/updated_at；recover({id,backup_revision}) 恢复已预览备份，保留损坏原文件。最近列表增加 damaged/recoverable。

# 1.0.2 年级接口（已实现，可联调）

`new({name,grades})` 创建考试；省略 grades 与显式 [] 都创建尚未设置年级的空清单。`state.plan.grades` 是所有年级下拉框和混排候选的唯一来源，包括暂时没有学生的已设年级。

`state.plan.grade_review_required`：旧文件缺 grades 迁移时 true，新方案 false。界面提示“旧方案已按原资料整理年级，请核对本次考试年级”。保存/确认年级清单时把该字段明确设 false；其他操作保留当前值。

`save({plan,revision})` 必须含 plan.grades，不能按本次提交资料推导清单。非空名称、重复别名、引用中删除、未知年级和非法混排组在提交前拒绝，不修改当前方案或文件。

`import_preflight/import` 的学生与科目行须引用已设年级。失败项为 `field: 'grade', code: 'grade_unknown', row: 源行号`；显式空清单提示先设置本次考试年级，实际导入拒绝且不部分提交。资料行的既有别名转换不扩充正式清单。

具名组使用 `settings.mix_presets=[{id,name,groups}]`。组名/稳定编号为文本，id 唯一，groups 至少一个组，每组至少两个正式年级、组间互斥。保存不自动应用；选择应用时前端明确更新 mix_grades/mix_groups。未覆盖年级独立，预设不改变 plan.grades。

旧文件整体导入及载入允许缺字段迁移；现代 save 省略 grades 直接拒绝。复制、方案导出、备份恢复均保留明确清单和核对标记。

导出范围 `scope.grades` 使用同一正式清单，已设但无学生的年级有效，预览显示“当前范围没有资料”。考号 `number_preview` 的 grade 同样先验证正式清单：选择已设但无学生年级返回 rows=[]、errors=[]，新增 warnings 中说明暂无学生、未生成考号；未知年级参数拒绝。不把清单中的空年级当成不存在。

## 1.1.0 已批准升级：后端契约（2026-10-12）

以下接口只编辑当前考试，POST 仍使用本机启动口令。新写接口必须携带最新 `revision`，确认时重新计算，不能把预览对象作为可信结果提交。返回 state 的操作成功后用整个新 state 替换旧状态；失败保留草稿。预览不落盘、不增加版本；预览中的新实体 ID 只供展示，最终 ID 以提交返回为准。新 capability：`edit_history / bulk_operations / subject_catalog / seat_labels / seat_adjust_preview=true`。

### 撤销与恢复

- `state.edit_history={count,can_undo,label,revision}`，显示最近一次已提交修改的名称。`edit_undo({revision}) -> state`，一笔撤销整个操作；最多50笔随方案保存，保存重开后可用，撤销仍增加 revision。包括普通资料/参数、批量操作、号码来源、锁定、座位、单科映射、监考及待复核标记。
- `state.plan.edit_history` 由服务管理，普通 save 忽略客户端对该字段的修改；实体补丁仅存改变的行，不嵌套历史或包含许可、输出文件、后台任务。复制、整体文件导入的新考试清空旧撤销链。备份恢复保留备份内的合法链且提升版本。
- 旧 `undo` 只能撤销最后一笔学生/监考调整，旧 `number_undo` 只能撤销最后一笔号码生成；其他资料已改变时拒绝跨越。新界面统一使用 `edit_undo`。无统一链的旧方案仍保留旧撤销的epoch保护。
- “恢复上次保存”由前端放弃本页未提交草稿，读取当前最新 state；不可调用备份 recover 回退其他已提交操作。外观偏好是独立本机设置，不在考试事务链中。

### 批量删除和修改

- `bulk_preview({kind,action,ids,fields?,reset_labels?}) -> {revision,kind,action,ids,rows,impact,requires_confirmation}`。
- `bulk_apply({同上,revision,confirm_impact?}) -> state`。`ids`必须非空且唯一；年级名称经别名规范化后也必须唯一。批量中任一项不合法，整批拒绝，不部分保存。
- `kind='grades',action='delete'`：ids是年级名。只允许未被学生、考试、活动混排组或具名混排预设引用的年级；错误信息列出关联数量，前端可按当前 plan 展开关联。不会隐式删除学生或混排组。
- `kind='students'|'teachers'|'exams'|'rooms',action='delete'`：ids是稳定编号。清理已删除实体的关联，整笔可撤销。
- `kind='rooms',action='update'`：fields只包含选中的 `code,name,location,rows,cols,per_desk,capacity,aisles,disabled,direction,order,availability,invigilators,seat_labels`；不在fields中的字段保留。通常座号交换走专用接口；恢复布局默认值需要 `seat_labels:{}`。同一请求可传 `reset_labels:true` 清除所选考场自定义标签后调整行列，先预览影响后一次保存、一次撤销。
- `kind='exams',action='update'`：fields允许 `date,start,end,duration,locked,invigilators,special_seating`，用于统一日程。起止完整时 duration按差值生成，不保存冲突分钟数。
- 删除/縮小/改变已用考场的形状：`impact={seats,removed_seats,locked_seats,monitors,requires_confirmation}`；seats含 `{exam_id,student_id,room_id,seat,locked,removed}`，monitors含 `{duty_id,room_id,assignments}`。必须明确 `confirm_impact:true`；不存在的新位置从相关映射移除，学生仍保留、待复核，不自动转到其他教室。监考影响与锁定完整列出后才可确认，撤销还原它们。
- 改方向/順排方式保持学生和未改动停用位的物理位置；行列变化前已有自定义标签必须显式 reset，不能悄悄丢弃。编号01～99、物理座位最多99限制不变。

### 考场创建和单场编辑

- `room_batch_preview/room_batch`在原 `{start,count,name_prefix,name_suffix,template_id?,revision?}` 上新增 `template:{位置及布局字段}`；也可复制 template_id。二者同时提供时template_id优先。预览返回rooms与revision；确认时重查编号冲突。template不必是已有考场，name/code/id会为新考场重新生成。
- `room_change_preview({room,reset_labels?}) -> {room,layout,revision,requires_confirmation,impact}`：原 room 完整对象，计算实际使用容量与删除/縮小影响，供单场编辑确认。
- `room_save({room,revision,reset_labels?,confirm_impact?}) -> state` 使用相同预检；不能用单场保存绕过批量的确认保护。`room_layout_preview({room})`仍只预览布局、不会提交。
- `defaults({group}) -> {group,values}`只取值、不修改方案。group为 `seating,monitors,numbering,solver,room_layout,appearance,report_layouts,subjects`。前端把values合并进本组草稿再按原流程提交；名称、年级、学生资料与实际日程不清空。subjects恢复内置目录时保留已使用自定义科目预设。无默认值的业务資料用草稿恢复。

### 科目目录和分钟时长

- `state.subject_catalog` 与 `plan.subject_catalog=[{name,duration}]`：独立于 plan.exams 的科目模板，随考试方案保存、复制和转移；旧方案补内置目录。每条默认时长为1～1440整数分钟，名称唯一且非空。
- `subject_catalog_save({catalog,revision}) -> state` 替换目录，一笔可撤销；绝不追溯修改已有科目日程。新科目可直接输入名称，不要求预先加入目录。
- `subject_batch_preview({grades:[名称],subjects:[名称或{name,duration}],date?,start?,end?,duration?}) -> {exams,duplicates:[{grade,subject}],revision}`。年级只取本次正式清单；已有/重复年级×科目条目列入duplicates，剩余条目预览。统一duration覆盖本次所选模板输入；统一起止时间完整时按差值覆盖分钟。
- `subject_batch({同上,revision}) -> state` 创建未重复的条目；已有条目不覆盖，全部可撤销。
- 保存、打开、整体导入统一规范化：起止完整时整数分钟=结束-开始（与是否已经选定日期无关）；起止不完整则保留有效计划时长，供求解使用；完整时段结束不晚于开始拒绝。
- Excel预检中映射了duration列且其数值与最终起止不一致（含部分更新与已有时间冲突），返回 `code:'duration_mismatch',field:'duration',row:源行号` 并禁止实际导入。修正原表分钟数，或取消时长列对应后再次预检，由时间计算。

### 两种座位调整

- 拖学生：`adjust_seat_preview({student_id,room_id,seat,exam_id:'base'或场次ID,swap?,locked?}) -> {revision,seats,number_review}`；确认调用现有 `adjust_seat`并传revision。移动/交换仍执行锁定、停用、容量、时间和单科范围等既有硬规则。
- 拖座号：`seat_labels_preview({room_id,first:整数,second:整数,action?:'swap'}) -> {revision,room,changes,positions,number_review}`；`seat_labels_apply({同上,revision}) -> state`。只能交换两个启用且容量内位置；changes列出各科学生新旧座号和锁定状态。学生和锁定留在原物理位置，改变该考场所有base/单科映射。
- `seat_labels_preview/seat_labels_apply({room_id,action:'reset',revision?})`恢复默认座号，同样保持物理位置、停用和锁定。与修改行列同时操作时用上面的 `reset_labels:true` 单笔布局事务，不先另行提交reset。
- `room.seat_labels`：完整的 `{'物理行:物理座位列':座号整数}` 置换，空对象表示默认横/竖、顺排/S型。座号必须完整1～总座位数且唯一；row/col均从1开始，col=桌列×每桌人数。普通save、load、整体import均校验，不接受部分映射或重复号。
- 界面使用state.layouts/physical_layouts，编排、统一检查、名单/座次表/桌贴与Excel/打印HTML全部读取同一布局函数。容量先限定物理可用位置，展示/分配列表按当前座号排序。
- 改座号不自动重写任何考号。`number_review`和统一检查列出生成号不一致，前端到原number_preview预览/明确生成；人工号保留。该行为仍适用于按方向修改和形状调整。

### 许可和正式包保护

源码接口兼容现有License/Ed25519格式、独立产品`exam-room-tool`、原公钥和联系配置；试用仍3天，到期可编排查看保存，考务材料的导出/预览/打印需要激活。损坏状态返回 `license.broken:true,canExport:false` 和简单中文说明，可正常打开保存方案，不初始化一份新的无限制许可。

正式包在隔离stage编译 `_license_impl`；原源码不搬移/删除，公钥SHA写入编译实现。正式包必须实际加载native模块并匹配本产品和原公钥指纹；缺模块、Python替代实现、无效配置或换公钥均锁导出。包内自检记录 `license_module_kind,license_product,license_public_present,license_state`，真正调用许可导出检查；冻结smoke必须收到同一进程run_id的native/product成功回执。源码与模拟包装测试不是Windows实际包内/实机验收。

新增前端editing.js/dragging.js预留在静态白名单，文件实现归前端。本轮后端不修改UI、独立验测工具、真实资料或许可私钥。

末轮核对：`solve/confirm`兼容旧请求，但带revision时严格拒绝过期版本，新前端须传版本。已有错误座位不会触发无关教师/名称/位置修改的布局确认，也不会趁该次修改被清除；仅本次实际布局改变/删除产生的影响进入impact。批量rows为服务端规范化的最终值（删除时为删除前选中对象），包括容量钳制结果，前端应展示rows，不只展示原fields请求。
