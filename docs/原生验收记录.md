## 可执行入口与CI交接

依赖：Python3.12、requirements.txt、requirements-dev.txt；pywebview在Mac须有PyObjC/WebKit，在Windows须有pythonnet及可用WebView2。独立材料检查使用openpyxl和pypdf。PDF仍由产品寻找已有Chrome/Edge；缺失不能用HTML伪装PDF通过。

只准备清单及虚构方案，不需要仓库中的历史output：

```text
.venv/bin/python tools/native_acceptance.py --mode prepare --output output/native-acceptance/prepare
```

执行本机原生宿主自动专项：

```text
.venv/bin/python tools/native_acceptance.py --mode run --platform mac --baseline /本次full目录/report.json --output output/native-acceptance/mac
python tools/native_acceptance.py --mode run --platform windows --baseline /本次Windows-full目录/report.json --output output/native-acceptance/windows
```

CI建议：三方冻结后，由总协调统一放行本平台`.venv/bin/python tools/run_testbench.py --mode full`（Windows用其Python解释器）；完成后读取output/testbench/latest.txt，把该目录/report.json传--baseline。不得伪造基线、用prepare/quick/中间报告代替，也不上传整个历史output作为“已通过”。Windows PowerShell先用`$nativeRunDirectory = (Get-Content output/testbench/latest.txt -Raw).Trim()`读取目录，再用`$nativeBaseline = Join-Path $nativeRunDirectory 'report.json'`构造参数；不得在开发中反复触发full或workflow。

参数：--mode prepare/run；--platform auto/mac/windows；--baseline完成且通过的full report.json；--output独立路径。不指定baseline的本地run尝试读取latest.txt，CI必须明确传该平台实际生成的路径。产品指纹与所给full不同则拒绝放行；新增验收工具不冒充产品变化。

退出码：0仅表示所选准备或本机自动专项执行成功；1为失败/空结果/文件变化；2为环境阻塞。prepare退出0**没有原生执行**。Windows没有交互window station、缺依赖或在Mac请求Windows，native记录阻塞，不能把源码浏览器、构建成功算原生通过。后端独占workflow和packaging，本测试对话不修改其文件。

每次产出report.html/report.json、terminal.json、checklist.json、虚构方案；run另有first/reopen独立子进程日志、请求、材料和窗口状态。子进程监督150秒，失败与超时非零，不覆盖首次失败。

## 自动化范围与边界

创建真实App、本机HTTP和pywebview窗口，Mac确认WKWebView实例及renderer，Windows须实际WebView2。通过evaluate_js触发DOM控件及等待页面反馈；不是实际系统键鼠/IME。窗口隐藏且不取焦点；Mac测试进程禁止NSApplication激活，避免抢前端桌面验收窗口。该设置只属于测试进程，不改变产品源码。

虚构目录名称含中文及空格。首次和重开分属独立进程、新App/新端口；检查中文信息与编排保留、版式、16类Excel、预览/实际PDF、真实文件损坏恢复及版本、测试试用到期/保存/激活及重启许可保留。签发私钥只在内存；不写口令、激活码到报告。PDF不是WKWebView原生打印；文件读写/恢复不替代系统文件选择和另存对话框。

此入口独立创建真实App及窗口，当前运行源码，**不是**生产app.main整体启动路径或冻结程序包入口。生产窗口关闭、系统文件操作、原生打印、真实升级及包内验证待前端/总协调相应环境另验。
