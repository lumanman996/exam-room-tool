# 构建与发布

## 试用与激活（与匀班、分寸做法一致）

公开仓库里只有入口 `exam_room/licensing.py`。下面这些只在管理员本机保存，已写进 `.gitignore`，绝不上传：

| 文件 | 用途 |
|---|---|
| `exam_room/_license_impl.py` | 试用与激活的验证实现，打包时编译成机器码 |
| `exam_room/_license_public.json` | 公钥和激活窗口里显示的联系方式 |
| `admin/` | 私钥、随身发码器、发码记录、一键备份和发码工具，用法见 `admin/说明.md` |

- 源码运行缺少验证模块时不做限制；正式安装包里缺少验证模块，或者模块被换成源码，就锁住导出和打印，查看、编排和保存仍可使用。
- GitHub 构建时，`_license_impl.py` 从保密项 `LICENSE_IMPL` 放入，公钥配置从仓库变量 `EXAM_ROOM_PUBLIC_CONFIG` 写入。改了验证模块后，运行 `.venv/bin/python admin/工具/pack_secret.py | gh secret set LICENSE_IMPL`；改了联系方式后，同步更新仓库变量。
- 产品标识为 `exam-room-tool`，与另外两个产品不同。试用 3 天，一码一机。不要重新生成密钥，否则已经发出的激活码全部失效。

## 本机构建

在对应平台 Python 3.12 环境安装 `requirements-dev.txt` 后执行：

```bash
python -m playwright install chromium
python packaging/smoke_test.py --report output/源码自检.json
python tools/run_testbench.py --mode full
# 从 output/testbench/latest.txt 读取本次目录，将下行路径替换成其 report.json。
python tools/native_acceptance.py --mode run --platform mac --baseline /本次full目录/report.json --output output/ci/native
# Windows 将上述 --platform mac 改成 --platform windows。
python packaging/build.py
python packaging/smoke_test.py --frozen --report output/包内自检.json
```

当前候选应用版本 1.0.2，方案格式 version 仍为 1。Mac 包：`dist/exam-room-tool-Mac.zip`。Windows 包：`dist/exam-room-tool-Windows.zip`。构建前验证公钥和必需说明资料；Mac 用 ditto 保留应用包权限和符号链接。

构建工作目录为 `output/build-runs/时间-随机编号/`，保存 build.log、manifest.json 和临时产物，不清空旧 build/dist。生成候选成功后才替换同平台交付；发布失败恢复旧目录，旧 zip 采用临时文件原子替换，另一平台及其他已有文件不受影响。可用 `--output 路径` 和 `--work-dir 路径` 指定位置。本脚本只生成内部候选，不自动公开发布。

每个交付目录包含程序、`使用手册.md`、`开始使用.txt`、四类空白 Excel 模板、`虚构示例方案.json` 和 `交付清单.json`。模板调用 importer.template 后移除数据示例行；虚构方案名称及学校明确标示用途。清单记录应用版本、平台、架构和逐文件 SHA-256，构建 manifest 另记录归档 SHA-256。候选包不包含 admin、测试 output 或用户方案；手册必须由前端冻结后再最终构建。

打包显式收集 OR-Tools、certifi 证书与所选平台 pywebview 宿主，并依赖官方 PyInstaller hooks 收集 Windows WebView2 桥接库。是否包内完整可运行仍须实际冻结程序自检，不以支持脚本测试代替实际构建。smoke_test 的 report 记录真实退出码/输出/隔离方式；Windows windowed 程序可能无 stdout，明确记录未观察到 JSON，不伪造结果。自检不打开原生窗口，原生宿主须另验。

Mac 与 Windows 需要分别构建。手动触发 GitHub Actions 可选 windows/mac/both，默认 Windows。使用 windows-2022 x64 和 macos-14 arm64，记录并断言真实架构；runner 标签依据 [GitHub 官方环境说明](https://docs.github.com/en/actions/reference/runners/github-hosted-runners)。CI 的 Windows Server 环境不等于 Windows 10/11 实机验收。

工作流使用仓库变量 `EXAM_ROOM_PUBLIC_CONFIG`，仅为公钥配置，不上传私钥。依次安装验测依赖与 Playwright Chromium、运行源码隔离自检、本平台完整 `full`、原生宿主自动专项、构建、冻结程序隔离自检。`full` 已含 Python/Node 回归，不重复执行同一批测试。源码自检和 full 必须实际通过；原生专项按下述退出码分支处理，构建及冻结自检必须实际成功。

CI 从本次 `output/testbench/latest.txt` 读取确切 `report.json`，验证报告已完成、六阶段全部通过且源码指纹稳定，再传给 `native_acceptance.py --mode run --platform windows/mac --baseline 确切report --output output/ci/native`。不引用本机历史报告，不以 prepare、quick 或中间快照作为基线。

原生退出码原样记录：0 为源码隐藏原生宿主自动专项通过；1 为失败；2 为环境阻塞。退出 1 停止候选构建；退出 2 明确标记环境阻塞，在同平台 full 与源码自检通过的前提下，仅继续生成“内部待实机验收候选”及执行冻结自检，不能写成原生通过或用浏览器结果替代。没有真实桌面会话、缺少 WebView2 等环境问题时，查看 `output/ci/native-status.json`、native 下的 report/checklist/terminal 与日志；总协调已明确授权这一内部候选分支，无需重跑一轮相同 CI；退出码和报告不一致、缺少报告或包含实际失败均拒绝继续。自动专项成功也不等于最终包、系统文件对话框、真实打印与升级验收通过。

任何依赖、源码、完整流程、原生、构建或冻结自检失败，以及原生环境阻塞，都保留该次日志与报告。证据附件仅上传本次 CI 的 output/ci、output/testbench 和构建 manifest/log；成功的包以 `exam-room-tool-internal-pending-device-acceptance-平台-运行编号` 保存为私有附件；不发 Release，不宣布正式交付。

总协调已建立本项目私有仓库并配置公钥变量，提交及触发由总协调统一操作。私有仓库 Releases 的匿名下载不可假定可用，现有更新器不携带账户凭据；内部候选先手动交付，正式公开更新渠道及实际升级另验。

工作流接入已完成本地 YAML、10 个 shell 步骤、4 段内嵌 Python 语法验证，以及 9 组原生退出码/报告门禁模拟；证据见 `output/platform-preflight/workflow-gates/verification.json` 和 final-verification.log。模拟不执行完整测试、原生窗口、构建或远程 CI，不作为 Windows/Mac 平台通过证据。正式触发仍由总协调在新功能完整回归通过后统一操作。

## 平台准备记录

`output/platform-preflight/environment.json` 记录本机 Mac arm64、Python 3.12.13、PyInstaller 6.22.3、pywebview 6.2.1、PyObjC 12.2.2、CP-SAT/Excel/加密依赖可导入、公钥 Ed25519 格式有效。Mac 实际隐藏 Cocoa/WKWebView 加载/销毁探针见 native-cocoa.json；此探针早于年级功能新增，不能替代当前版本完整原生验收。1.0.2 源码隔离自检见 source-selftest-1.0.2.json。

当前本机未找到可用 Windows 虚拟机/宿主；远程 Windows 由已授权私有 Actions 渠道统一构建并保存真实日志。本机无 Developer ID 身份，可先进行本机/内部试用候选，公开签名公证留待正式发行；notarytool 存在不代表公证凭据已配置。

默认数据位置：Mac 候选为 `~/Documents/考场编排`，许可为 `~/Library/Application Support/ExamRoomTool`；Windows 为免安装程序所在目录的 data/output，许可在 LOCALAPPDATA/ExamRoomTool。Windows 应解压到普通用户可写目录，不使用受保护的 Program Files；方案文件可搬移，直接换到另一程序目录不会自动迁移 data。`EXAM_ROOM_HOME` 仅用于隔离测试，需避开真实资料。

更新器保留 Windows data/output 和已有 config；Mac 数据/许可独立于应用包。已有原子保存及许可边界回归不等于真实平台升级通过。不要重新生成产品许可公钥，否则既有激活会失效。当前版本退出/重启、真实系统文件选择、WebView2 Runtime、普通用户路径与真实升级都要在对应宿主继续验收。

## 正式分发验收

1. Windows 10/11 与 Apple 芯片 Mac 分别启动、导入样例、完整编排、打印、关闭后重新打开。
2. 验证三天试用到期后仍可保存，导出被阻止；激活后恢复导出。
3. 在升级前保存方案，并验证更新后的方案和许可记录保留。
4. Mac 使用产品开发者身份签名并公证后分发；开发测试包使用本地临时签名。
5. 发布到本项目 GitHub Releases，资产名以 `exam-room-tool-` 开始，以 `-Mac.zip` / `-Windows.zip` 结束。更新模块只接受本项目发布下载地址，并校验服务器提供的 SHA-256 摘要。

公开发布、签名公证和更新安装需在真实发布环境确认。本机生成包不等于已完成跨平台正式发行。
