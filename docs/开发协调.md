## 3. 当前工作顺序

### 阶段 A：并行开发和针对性测试

- 后端优先修复统一资料检查、手工日程允许时段、参试科目匹配、成绩字段变更失效、监考锁定关联；随后完善导入变更、撤销保护、恢复及导出快照。
- 前端先完成导航、明暗主题、跟随系统、字号增减与恢复、密度、搜索分页和保存反馈；再完善座位、考号、监考、检查定位及导出工作区。
- 测试完成隔离执行、独立核对和报告，先验证关键规则与接口；现有界面流程可作阶段检查，随前端改造更新行为定位。
- 每项功能改完先实际运行相关测试；失败先修复、复测。测试未运行、环境缺失和实现未完成分别说明。

### 阶段 B：接口交接和联调

接口逐项记录在 docs/前后端接口约定.md，由后端维护。前端提供需求并确认接入，测试核对异常、revision 和落盘结果。不得仅凭函数存在标为就绪。

必须交接：导入预检及替换/更新、问题分阶段与对象定位、修改影响、物理布局、损坏方案恢复、监考候选与原因、总表排版保存/预览/导出、后台导出状态/取消。每项需要请求、返回、中文错误、并发保护、旧方案兼容及测试证据；尚无实现者标为待实现，不先展示可用按钮。

界面偏好在本机跨考试保持；修改主题/字号不使编排失效。打印使用白纸底，打印字号与界面字号分开；总表版式随方案保存，以同一 revision 的方案生成预览和导出。

### 阶段 C：稳定源码的完整验测

前后端交接时分别报可验测范围、测试证据和未完项。完整验测开始前确认相关文件不再修改；如中途改动，受影响结果失效并重新运行。

由测试对话统一执行：导入 → 日程 → 座位 → 考号 → 监考 → 人工调整与锁定 → 保存重开 → 检查 → 正式/草稿导出。还须验证失败恢复、版本冲突、过期预览、四种座号路线、混排和许可边界。

独立核对方案、实际界面与 Excel/HTML/PDF 的人数、考号文本、物理位置、参试场次及教师；覆盖全部材料，不用产品自身 validate 作为唯一正确性证据。长姓名、长考号、跨页、主题、字号及窗口尺寸需要浏览器运行和截图检查。

验测报告至少记录运行起止时间、平台、Python/求解器版本、Git 提交、参与运行的源码内容指纹、样本指纹、实际命令、退出码、通过/失败/环境阻塞/未运行、证据路径。同一未提交工作区只记录 Git 提交和修改文件名不能唯一确定版本；运行前后核对源码指纹以识别期间改动。

### 阶段 D：最终构建与平台交付

源码完整验测通过且阻断问题关闭后，才统一安排 Windows/Mac 最终构建和包内自检。各平台原生窗口、系统文件操作、打印、许可与升级分别验证；Mac 浏览器或源码测试不能替代 Windows 实机验收。包内问题仍需修复并复测。
