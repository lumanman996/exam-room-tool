# 第一版内部数据协议

所有字段为 JSON 可序列化对象，时间是本地考试日期 YYYY-MM-DD / 时间 HH:MM。所有实体 id 为字符串。无成绩是 null。实体关联只用 id，姓名可重复。

方案对象：
```
{version:1,id,name,school,created_at,updated_at,
 students:[],rooms:[],teachers:[],exams:[],
 settings:{mode:'class',seed:42,mix_grades:false,mix_groups:[],invigilators:2,
 avoid_subject:true,avoid_class:true,number_prefix:'',number_width:5,number_start:1,
 slots:[],time_limit:30,font_scale:1,score_field:''},
 seats:{base:{}},invigilation:{},history:[],revision:0}
```
- student: `{id,name,grade,class_name,student_no:'',number:'',score:null,subjects:[],original:{}}`。subjects 空代表参加年级所有科目。
- room: `{id,code,name,location:'',rows:5,cols:6,per_desk:1,aisles:[],disabled:[],capacity:30,order:'straight',availability:[],invigilators:null}`。cols 为桌列，每桌 per_desk 个左右相邻座位；disabled 为数字座号。aisles 为过道之前的桌列号（1-based）。availability 空代表一直可用，否则 [{date,start,end}]。直排按行从左至右，snake 每第二行反向；容量最多为实际启用座位数。
- teacher: `{id,name,subjects:[],classes:[],unavailable:[]}`。classes 为班级名称，建议带年级（如七1）。subjects 为学科名；unavailable 是 [{date,start,end}]。
- exam: `{id,grade,subject,duration:90,date:'',start:'',end:'',locked:false,special_seating:false,invigilators:null}`。
- settings.slots 为 [{date,start,end}]；mode 为 score/random/class。mix_groups 为年级字符串数组的数组，空且 mix_grades 为真时表示全部年级。
- seats.base 为 student_id -> `{room_id,seat:整数,locked:false}`。特殊科目使用 seats[exam_id] 完整映射该科学生；其余科目使用 base。座号从 1 开始。
- invigilation 为 duty_id -> `[{teacher_id,locked:false}]`。
- history 为可撤销调整快照 `{label,seats,invigilation,stale,special_seating}`，最多 50 步；原始资料编辑不在撤销范围。

核心引擎接口（engine.py，只由核心实现者编辑）：
- `seat_layout(room) -> list[{seat,row,col,desk,side}]` 返回可使用座位，row/col/desk/side 均从 1 开始。col 是真实座位列（cols * per_desk）。disabled 与容量限制在此处理。
- `participants(plan, exam) -> list[student]`
- `duties(plan) -> list[{id,room_id,date,start,end,exam_ids,student_ids,subjects,classes,required}]`。同房间同起止时间合并为一场监考；id 为 `room_id|date|start|end`。
- `validate(plan,include_stale=True) -> {errors:[issue],warnings:[issue],summary:{...}}`。issue `{code,message,...可选实体id}`。覆盖资料缺失、考号、时间、容量、座位、混排、监考（含回避）规则；未编排也如实报告。
- `schedule(plan,cancel=None,progress=None) -> {status,message,plan}`
- `assign_seats(plan,cancel=None,progress=None,exam_id=None) -> {status,message,plan}`。不改变输入；base 或特定科目编排；保留锁定位置；尊重时间共享教室和混排设置。
- `assign_invigilators(plan,cancel=None,progress=None) -> {status,message,plan}`
- status: optimal/feasible/partial/infeasible/timeout/cancelled/invalid；cancel 为 threading.Event；progress 为 callable(str)。CP-SAT 超时无结果不等于 infeasible；partial 返回可用教师和明确待补位置，不放宽回避条件；invalid 表示模型未通过检查，不代表已证明无解。
- `adjust_seat(plan,student_id,room_id,seat,exam_id='base',swap=False,locked=None) -> plan`，调整检查座位硬规则（不要被无关的未安排监考阻挡），保存 history，逐步撤销由服务处理。
- `adjust_invigilator(plan,duty_id,index,teacher_id,locked=False) -> plan`，检查教师时间、回避、可用性，允许 teacher_id='' 清空。
- `workload(plan) -> list[{teacher_id,name,count,minutes}]`

所有新方案/导入数据规范化由 model.py 实现。日程、座位与监考编排返回完整新方案，由后台任务以 revision 乐观并发检查后提交，不能覆盖用户期间的新编辑。report.py 的正式导出以 validate 为门禁；草稿允许问题并打草稿标识。

2026-10-06 兼容补充：settings.number_rule 为 seat/serial，默认 seat；number_prefix 仍按文本保存，通常 2～4 位，长度不固定。seat 格式为前缀 + 两位考场编号 + 两位座位号，以 seats.base 为来源，编号为 01～99。number_sources 为 student_id -> {prefix,room_id,number}，仅跟踪程序生成且尚未人工改号的学生；固定位置或考场编号变化产生 number_seat_mismatch 硬性问题，特殊科目位置变化不改变考号。number_history 独立保存最近 10 次生成之前的号码、来源和设置；不与座位撤销混用。

新增接口：number_preview / numbers / number_undo，room_batch_preview / room_batch / room_layout_preview / room_save。预览与确认之间使用 revision 检查；确认会重新执行范围、位置及唯一性校验，不信任客户端预览行。考场批量编号和编辑器保存限制为 01～99；布局包含物理位置、停用状态和容量内位置，座号规则仍共用 seat_layout。旧方案格式版本不变。

### 1.0.1 编号方向与混插

- rooms.direction：horizontal（默认，横排）或 vertical（竖排）；order：straight 或 snake，与方向独立组合。座号始终递增，row/col 是以讲台在上方的物理位置；双人桌 col 指座位列，desk/side 保持物理桌位置。停用座位及容量仍按座号处理。旧文件无 direction 时补 horizontal。
- settings.mode 增加 number（已有考号升序）。不更改号码原文本，纯数字按数值排序，其他文本按字典序，空号码最后，稳定编号消除同分歧义。
- 混排按钮继续读写 mix_grades 与 mix_groups，无新并行规则字段。完整参试时段一致且任意两组允许混排的年级在可用座号中轮流分配，锁定位置保留。特殊参试时段保留求解器安全分配。
- 日程保存日期、HH:MM 起止时间及分钟 duration，修改日程/方向仍经 api_save 标记 seats/invigilation 待复核。前缀 + 两位考场号 + 两位座位号格式保持不变。

### 后端完善与报表接口（2026-10-07）

- 同为 version=1 的兼容扩展：settings.exam_groups=[{exam_ids:[]}], settings.number_prefixes={年级:文本前缀}；plan.report_layouts={材料key:版式}；history_epoch、change_log、stale_seats、pending_monitor_locks。旧方案未带这些字段时自动补默认值。
- validation 增加 stages，分 data/schedule/seats/numbers/monitors。统一资料规则对导入、编辑、打开和编排均生效；可保存缺项草稿，正式材料依所选材料的 export_stages 门禁。手工日程设置了 slots 时也必须处于允许时段。参试科目须匹配本年级科目。
- 保存资料通过 changes.reconcile 迁移关联；修改座号方向/顺排方式而行列形状不变时，保持原物理座位并重新计算座号。单科重排只清除该科的 stale_seats；不同参试时段或人数不等使交插不完整时以具体连续座号提示。
- history 快照增加 epoch/stale_seats/pending_monitor_locks；资料或规则改变后，不允许旧快照覆盖新资料。考号撤销也使用 epoch；更改号码后的人工修改仍会阻止覆盖。
- 同时提供统一 prefix 与本次 prefixes 时，优先本次的年级覆盖。未提供本次年级覆盖时，显式 prefix 保留旧入口行为；没有显式 prefix 时沿用保存的年级前缀，再用统一前缀。
- 监考日期/起止时间改变时，按稳定考场与考试编号迁移锁定；合并锁定冲突、监考人数减少造成的失效位置必须明确处理。monitor_candidates 提供可选教师及不可用/回避/重叠原因；monitor_lock_resolve(action='discard') 明确解除冲突，绝不自动放宽规则。
- 保存采用唯一临时文件、flush/fsync 和原子替换；损坏主文件不覆盖有效备份。恢复保留损坏原件，revision 大于当前方案与备份，阻止旧任务覆盖。删除/还原同时移动备份；损坏原件也可以进回收站后恢复。
- 新材料 room_students 是按固定参试时间分组的考场总表，科目有效范围使用 effective map；student_details 是每科一行。原 students 含义不变。准考证/桌贴的姓名、班级和考号在每个独立分块标题中，科目与有效位置在表内，Excel 同样保留身份标题。
- 版式单位、保存、真实分页、后台导出、取消及异常约定详见 [前后端接口约定](前后端接口约定.md)。后台任务固定方案快照，期间新修改不会写入正在生成的材料；结果返回 snapshot_revision/stale。到期仍可查看、编排与保存，但预览/打印/材料导出在入口与发布文件时检查许可。
# 1.0.2：本次考试年级清单

方案格式版本仍为 `version: 1`。新增顶层 `grades: list[str]` 和 `grade_review_required: bool`，应用版本为 1.0.2。

- `grades` 是教务设置的正式范围，顺序按输入保存。名称必须是非空文本，不能重复；七/初一/7年级等现有别名统一为七年级，自定名称原样保留。
- `new_plan()` 明确保存 `grades: []`，绝不因后来学生或考试科目出现而扩充。未设清单时可以保存空考试、设置考场和教师，学生及科目须先设置年级后录入。
- 仅旧方案缺少 `grades` 字段时，从其已有学生及科目资料按出现顺序整理年级，置 `grade_review_required: true`。迁移标记持久化，重开不会丢失；新方案为 false。教务核对清单后可在保存年级设置时明确改为 false，普通其他保存不得自动替用户确认。
- 保存当前考试必须携带 `grades` 字段；省略该字段不能重新进入旧文件迁移。学生/科目引用未知年级、删除仍被引用的年级或组内引用无效年级，保存失败且旧方案、版本和文件不变。
- `settings.mix_presets: [{id,name,groups}]`：编号唯一且稳定、名称非空、至少一个混排组；每组至少两个已设年级，组内及组间不重复。未覆盖年级独立。存储预设不自动改变 `mix_grades/mix_groups`，应用预设仍通过现有活动字段。
- 年级清单变更增加调整 epoch，并把已有日程、座位和监考标记待复核；纯粹保存或重命名未应用的混排预设不使当前编排失效。
- 未知年级为 `grade_unknown`，归统一检查的 data 硬问题，学生/科目的具体字段为 `grade`；求解及所有正式材料不可绕过。已有允许的缺项草稿规则不因此自动补齐资料。

## 1.1.0：事务、模板与物理座号（2026-10-12）

方案格式仍version=1。旧文件无新字段时按原行为补默认值，不改变稳定实体ID。此前“普通资料不在撤销范围”的描述由以下统一事务规则取代。

- 顶层 `edit_history` 最近50笔：`{label,kind,at,revision,before,entities,after,absent}`；before只存变更的非实体字段，entities按资料类别保存变动行的旧值、新增ID和必要的原始顺序，after是变动字段的当前SHA256（字段被移除则null）。绝不递归保存edit_history、旧部分撤销快照、许可、输出文件或任务。字段白名单拒绝回退id/version/revision等元信息。
- `edit_undo`校验当前指纹后整笔恢复；revision始终从服务当前版本加一，旧后台结果依旧被拒绝。恢复完整实体关联、号码来源、锁定、各科映射及待复核；旧局部history/number_history不跨越统一事务，统一撤销后清空这些局部快照，后续使用全局链。复制/整体文件导入开启新链；备份恢复仍使用严格提升的revision。
- 顶层 `subject_catalog:[{name,duration}]` 与exams分离。内置语文/数学/英语/物理/化学/生物/道德与法治/历史/地理/体育；目录修改仅影响以后新增条目的模板，不改旧日程。随方案保存与转移。起止完整的exam.duration统一计算为分钟差；未定时保留1～1440的整数计划分钟。Excel冲突需在预检中解决。
- `room.seat_labels:{'row:col':整数}`：完整物理坐标到座号的1～总座位数置换，默认`{}`。桌行row、真实座位列col均从1开始。旧room无此字段补空映射；错误部分映射、重复座号、与行列不一致映射在save/load/import都拒绝。
- seats仍存 `{room_id,seat,locked}`，seat为当前标签。更换标签/方向时依据旧布局求物理位置，再映射新标签；所有base和单科使用同样转换，锁定不移动。disabled仍记录标签，但未修改停用设置时随编号变更保持同一物理停用位。容量先取物理布局中的可用位置，返回按当前标签排序；各科、检查和打印共用同一个计算器。
- 缩小/删除已用教室先显示受影响学生/锁定/监考并明确确认；不在新布局内的位置从映射移除并标待复核，不移动到其他考场。已有自定义标签改变形状须显式恢复默认，可在同一预览/确认事务内reset_labels。撤销还原整笔状态。
- 学生number原文本不因更改标签而覆盖；生成号的number_sources保留以显示number_seat_mismatch，人工号不隐式更新。号码生成仍原预览与确认流程。

准确请求和返回对象见[前后端接口约定](前后端接口约定.md)。本机显示偏好与考试事务分开，未提交草稿恢复由前端管理。
