# 考场编排·验测台资料包

所有学校、学生、教师、成绩及安排均为虚构，供考场编排测试使用。不要填写真实资料。

## 已准备好的内容

| 内容 | 数量／规模 | 用途 |
|---|---|---|
| 方案场景 | 27 份 JSON | 正常流程、人工调整、规则冲突、兼容与规模 |
| 导入专项场景 | 9 份文件 | 多工作表、标题行、别名、编码、缺项、重复及坏文件 |
| 四类导入表 | 3 组 × 4 类 × 2 格式 = 24 份 | 12 人、144 人、1,500 人的 Excel 和 CSV |
| 小样本标准答案 | 3 份明细 JSON + 1 份布局 JSON | 手工预期，防止只依赖产品自检 |
| 场景清单 | cases.json | 输入、操作步骤、预期问题、数量与求解状态 |
| 验收记录模板 | 验收记录模板.xlsx | 软件完成后填写实际结果、证据与复测 |
| 文件指纹 | inventory.json | 每份样本大小及 SHA-256，判断是否被改动 |

cases.json 内的状态是场景定义，保持「未运行」；每次实际结果写入 output/testbench/ 独立报告。自动执行器、HTTP 场景、浏览器脚本和中文报告已实现。准备检查成功不等于完整流程通过。

## 先使用这三组

1. **C01_tiny_completed：12 人小样本。** 七八年级各 6 人，2 场×6 座、4 位教师、6 科考试。已经手工排好；检查、导出、保存重开可直接开始。学生考试明细应有 36 行；前缀 001，首位学生考号是文本 `0010101`。标准答案在同目录 `golden_expected.json`。
2. **C02_normal_144：常规完整流程。** 七八九各 48 人、各 3 班、6 场×30 座、18 位教师、9 科考试。座位和监考尚未安排；按已定日程编排后，学生考试明细应有 432 行。四类表可分别上传，或直接打开方案 JSON。
3. **C20_large_mixed：学校规模。** 七八九各 500 人、各 10 班、50 场×30 座、120 位教师、9 科考试，允许三年级混排。编排后学生考试明细应有 4,500 行。大样本不放在每次快速检查中反复运行。

表格导入是原始资料，没有 JSON 内的锁定、位置或监考结果。测试「已完成标准方案」应打开 JSON；测试「从零导入」应上传四类表。表头与中文字段符合当前导入协议；编号按文本存储。

## 导入专项

`fixtures/imports/` 包括多工作表标题行、GB18030 中文 CSV、别名与原始成绩列、重复考号、缺姓名、损坏 xlsx、损坏 JSON、未知方案版本、错误教师时段。I01～I09 的步骤和预期在 `cases.json`。

损坏文件是有意制作的错误输入，不能当普通表格使用。重复号码和缺姓名的表格可读取，但新版确认导入前预检会指出问题，提交须原子拒绝并保留原方案。时段文本错误应在确认导入时拒绝。

## 自动执行

在项目源码目录执行：

```bash
# 只验证当前资料，不覆盖样本
.venv/bin/python tools/prepare_testkit.py --verify-only

# 确有需要时重新生成；会覆盖本包内的生成文件和验收记录模板
.venv/bin/python tools/prepare_testkit.py --verify

# 快速回归：资料检查、源码、前端单元、36 场景和 6 接口流程
.venv/bin/python tools/run_testbench.py --mode quick

# 完整源码验测：增加真实页面操作、Excel/PDF、1,500 人实际求解
.venv/bin/python tools/run_testbench.py --mode full
```

请先把填写过的验收记录另存，避免重新生成覆盖。生成器依赖本项目 `exam_room` 和 Python 环境，资料 ZIP 可直接用于界面导入，ZIP 内脚本需放在本项目源码环境中运行。

准备脚本仅写入 `testkit/` 和 `output/testbench-preparation.json`，不启动桌面程序、不读取正式许可、不改用户方案，也不构建桌面程序包。它检查样本数量、预期错误、手工明细与四种布局、四类表字段往返及指纹；不运行完整浏览器、跨平台和大规模求解验收。

## 软件完成后怎么测

详细规则和六条完整流程见项目 `docs/验测台测试方案.md`。按「核心规则 → 接口 → 完整界面 → 保存重开 → 材料逐项核对 → 回归 → 最终两平台包」顺序推进。每项保存实际证据，未运行和环境阻塞明确记录。

测试时用隔离目录与独立测试许可；从本包复制方案到工作目录。JSON 导入会创建新方案 ID，核对实体和安排时不要求顶层方案 ID 相同。

报告位置：output/testbench/时间戳目录/report.html 和 report.json；latest.txt 记录最近完整入口的目录。失败保留截图、页面操作轨迹、接口记录和 traceback。失败、环境阻塞、运行期间源码改变均返回非零退出码，不能放行。用户无需手动点击，可直接让开发代理运行并整理结果。


## 新年级规则下的自动验收（2026-10-08）

正向导入前应先设置本次考试年级。I01/I02/I03自动步骤先保存固定七/八/九清单，再导入原样本；不按导入结果反推或自动扩大范围。C07原样本保留空年级，先核对导入拒绝、原方案/版本/文件不变；仅在测试副本补回已知年级，再检验缺姓名/班级、正式导出拦截及修复。原fixture及其指纹不变。

完整入口现含13组页面流程，新年级独立HTTP11项纳入源码回归。正式原生自动入口为 `tools/native_acceptance.py`；prepare只是准备，run必须使用本平台本次已完成的full报告。所有实际结果写独立output目录，资料包不携带历史报告来代替本次执行。
